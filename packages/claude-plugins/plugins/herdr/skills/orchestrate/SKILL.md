# Herdr でのオーケストレーション

あなたはこれから Herdr で子エージェントを立ち上げ、作業を委任する親エージェント (オーケストレーター) になる。

前提: `herdr` (本体) スキルと `herdr:gotcha` スキルをロードしておく。

## 待ちの仕組み

親は子の状態をポーリングしない。**`herdr agent wait` でブロックしてはいけない。** ブロックしている間は子からの中間報告を処理できないうえ、その報告があなたのペインで実行中のコマンドへ流し込まれ、`herdr:gotcha` の入力行汚染を自分で踏むことになる。

代わりに、指示を送ったらターンを終える。子が `herdr agent prompt <あなたの pane ID>` であなたのペインを叩き、そのメッセージであなたが再起動される。以降は「報告で起きる → 次の指示を返す → またターンを終える」を、最終報告が来るまで繰り返す。

## 手順

1. 自分の pane ID を控える。子があなたへ報告するための宛先になる。

   ```bash
   herdr pane current --current # .result.pane.pane_id
   ```

2. 依頼文書を書き出す。

   委任ごとの使い捨てなので、置き場所はあなたのスクラッチパッドディレクトリ (システムプロンプトで指定されているもの)、ファイル名は `delegation-<子の名前>.md`。

   子はあなたの文脈を一切共有していない。次を省略せず埋めること:

   | 項目 | 内容 |
   |---|---|
   | タスク | 何をするか |
   | 完了の定義 | 何が揃ったら終わりか |
   | 作業ディレクトリ | 絶対パス。ブランチを指定するならそれも |
   | 親の pane ID | 手順 1 で控えたもの |
   | 中間報告のタイミング | 最低 1 回は挟む (下記) |
   | 参照先 | ファイルは絶対パスで、URL はそのまま |
   | 推奨スキル | `herdr:gotcha` を必ず含める |

   中間報告は作業の切れ目に必ず挟む。e.g. 調査と実装を任せるなら (1) 調査 → (2) 中間報告 → (3) 実装 → (4) 最終報告。

3. 子を起動して引き継がせる。

   `herdr` (本体) スキルの手順で兄弟ペインを split し、そこで子を起動する。

   ```bash
   herdr agent start <name> --kind claude --pane <split したペインの pane_id>
   herdr agent prompt <name> "/herdr:delegate-receive <手順 2 で書き出した文書のパス>"
   ```

   `/herdr:delegate-receive` は Claude Code のスラッシュコマンドなので、kind は `claude` 固定。

   この prompt 自体は自由記述テキストではなく固定形式 (コマンド名 + パス) なので、ダブルクォート直書きで構わない。

4. ターンを終えて、子からの報告を待つ。

   ターンを終える前に、**子の名前・pane ID と「報告待ちである」ことをユーザーへ伝える。** 子が落ちたり無言で `blocked` になったりすると誰もあなたを起こさないので、TUI を見ているユーザーだけが復旧経路になる。

   承認待ちや実行中のコマンドを抱えたまま終わらないこと。子の報告はあなたのペインの入力行に届くので、そこが空でないと今度はあなたが入力行汚染を踏む。

5. 報告で起こされたら、内容で分岐する。

   - 中間報告 → 確認して次の指示を子へ送り、手順 4 に戻る
   - 質問・相談 → 回答を送り、手順 4 に戻る
   - 最終報告 → 手順 6 へ

   子へ送る文面は自由記述テキストなので、`herdr:gotcha` の固定形式 (ファイルに書き出してから `"$(cat ...)"`) で送ること。

   報告と実状態が食い違っていないかは `herdr agent get <name>` で裏を取る。`blocked` なら `herdr agent read <name> --source recent-unwrapped --lines 120` で中身を読んでから対応する。子が自分から質問を送ってきた場合、子は `idle` / `done` になっていて `blocked` にはならない点に注意。

6. 後始末する。

   ```bash
   herdr pane close <子の pane ID>
   ```

   閉じてよいのは自分が作ったペインだけ。agent 名は live agent の間でユニークなので、放置すると次の委任で同じ名前が取れなくなる。ユーザーが子のペインを残す意向を示している場合は閉じず、その旨を伝える。
